# Process: directing the agent through evidence

I built *The Cursed Museum* with an AI coding agent, but I did not treat working code as proof of a good result. My role was to define the experience, challenge the agent's decisions, test its output, and turn repeated mistakes into lasting rules and checks. The repository previously held *Traces of ANU*, whose history remains before [`804aabc`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/804aabc). The four interventions below show where my judgement changed both the museum and the way I worked with the agent.

## Stack and working method

I chose one Node process using `node:http`, `node:sqlite`, and Server-Sent Events. SQLite fits a small shared museum: transactions make donations, accounts, and votes durable before broadcast, while a Fly volume carries one database across restarts. SSE fits the interaction model because clients mainly receive presence and collection changes; writes can remain ordinary validated `POST` requests. A WebSocket layer would add a second protocol and reconnection path without improving this one-way broadcast pattern. The cost is deliberate: this architecture targets one small Fly machine, not horizontal scaling.

**Image-generation workflow.** I did not choose ChatGPT without testing the free alternatives first. Following the course's [free-tier-first image-generation guidance](https://comp.anu.edu.au/courses/comp4020-agentic-coding-studio/topics/generating-images/), I used the free, keyless Pollinations API in `tools/generate-relic-assets.py` to generate eight donated-relic presets and three experimental accessory images ([`78ef073`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/78ef073)). This proved that generated cutouts could work in the donation flow, but the visual results were not consistently refined or faithful enough for the museum's Gothic theme. The first `tarnished-silver-spoon.png`, for example, had pink/green chroma-key fringing and lost the eye in the spoon bowl that made the reference object distinctive. An eyepatch accessory failed more decisively: eight regenerated prompts produced masked people, costumed figures, or an unrelated medallion instead of a standalone eyepatch, so I abandoned it rather than ship an unsuitable image.

These were practical comparison results, not an assumption that a paid or familiar tool must be better. I stopped using Pollinations for subsequent image generation and switched to ChatGPT/OpenAI ImageGen because its outputs were more detailed, polished, and visually consistent with the required Victorian cabinet-of-curiosities direction. The switch is visible in [`7b07136`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/7b07136): ImageGen replaced the failed-looking spoon with a cleaner, reference-faithful version and produced four additional relic presets and the customiser sticker set with richer colour, controlled warm lighting, aged materials, and clean transparent edges. From that point, all newly generated image assets in the remaining workflow used ChatGPT/gpt-image, including the 82 high-resolution object-detail reconstructions added in `b402686`, `d97e6cf`, `31c9cd9`, and `3248d79`. I still directed the prompts, compared and rejected outputs, checked each asset manually, and integrated the selected images into the catalog and interaction system. [ASSETS.md](ASSETS.md) preserves the per-category provenance, including the earlier Pollinations images that remain in the project; the decision was to stop using that tool for later generation, not to mislabel every existing image as ChatGPT-made.

My harness separates guides from sensors. [CLAUDE.md](CLAUDE.md) tells the agent that accounts are append-only, broadcasts follow commits, presence is room-scoped, and visual interaction must work with mouse, touch, and keyboard. The [spec map](spec/README.md) connects those rules to tests; CI repeats the checks in a clean container. I also used the running application as evidence. Screenshots, console output, API responses, two independent browser profiles, and narrow-view testing found visual and timing failures that green unit tests could not see. The following interventions show how this changed the work.

## Intervention 1: rejecting the technically successful museum

**Problem and diagnosis.** The first final-project version was a working free-roam Three.js museum with avatar movement, collision, two cameras, SQLite, donation, voting, and multiplayer. I nevertheless rejected it after using it: modular furniture and primitive geometry made every room feel like the same demonstration space. More movement had not produced more curiosity.

**Decision and agent correction.** I redirected the agent from adding detail to changing the interaction model. [`00e5c0a`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/00e5c0a) removed continuous movement in favour of a fixed scene graph; [`4c1652e`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/4c1652e) replaced generated rooms with authored illustrations while preserving the database and SSE work. [ADR 0003](docs/adr/0003-scene-exploration.md), [0004](docs/adr/0004-illustrated-scenes.md), and [0005](docs/adr/0005-immersive-2.5d-camera.md) record the rejected alternatives and the cost of abandoning reusable 3D geometry. The resulting [CLAUDE.md](CLAUDE.md) rule requires bounded navigation and galleries distinguishable without reading their signs.

**Verification.** I walked the actual scenes at desktop and phone aspect ratios instead of accepting screenshots of one viewport. The resulting [`04343e6`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/04343e6) fixed narrow-viewport camera bounds and added camera tests; [`207f3cf`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/207f3cf) then eliminated art/hotspot drift by fitting both layers with the same SVG rule. These were observed interaction failures, not polish inferred from source code.

## Intervention 2: making the agent’s vision editable

**Problem and diagnosis.** Object recognition consumed repeated prompts and produced approximate rectangles. An audit found 34 of 72 shapes were still four-point placeholders; one “chest” hotspot covered an ottoman. Asking the agent to inspect the image again changed coordinates but not the unreliable workflow. A separate scaling mismatch meant CSS room art and SVG hotspots drifted at narrow viewports, so retracing alone could never solve every offset.

**Decision and agent correction.** I stopped asking for another automatic answer and required an inspectable authoring tool. [`451231b`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/451231b) added a local editor for tracing and adjusting outlines against the source images. Its first automatic method subtracted a background colour, but painterly lighting fragmented objects into useless blobs. [`825d4af`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/825d4af) replaced it with SlimSAM: the model proposes an editable outline from my loose box, then returns control to me for correction. This turned agent guessing into a human-in-the-loop workflow. The model remains confined to the unlinked development tool, preserving the museum’s zero-runtime-dependency rule.

The lasting correction is recorded in [ADR 0011](docs/adr/0011-object-shaped-interaction.md) and [CLAUDE.md](CLAUDE.md): hotspots remain inspectable, share the room art’s coordinate system, and separate the precise outline from a forgiving click area (`hitPadding`, kept distinct from the visible glow shape). [The world checks](spec/world.test.ts) assert the inspectable half directly — every shape is real traced geometry, never a box, sharing one `viewBox` with the room art. The ADR carries the full implementation detail; a further eight retrace commits it names by hash (`434d013`, `f02b02b`, `3c5e31e`, `b7b5e56`, `250ce7d`, `c3c1d25`, `653eb04`, `a203810`) tightened outlines and fixed misnamed objects well after this one shipped, which is the expected cost of shapes that actually match the art, not a sign the tool failed.

**Verification.** I compared overlays with enlarged source-image crops and measured the two SVG layers with `getScreenCTM()` across rooms, pan/zoom states, and narrow viewports; the sampled delta became 0.000px. The SAM workflow was exercised in a real non-headless browser on the actual paintings, because mask quality cannot be established by a unit test alone.

## Intervention 3: a green fix that was visibly wrong

**Problem and diagnosis.** Rotating a long donated relic clipped it inside its unrotated container. The first agent fix, [`8fcf02c`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/8fcf02c), scaled the relic down enough to fit. Its [CI run passed](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/actions/runs/42493393759), but dragging the dial showed the object shrinking and growing as it turned. The check proved the code was valid, not that the interaction was believable.

**Decision and harness change.** I rejected that shipped fix. [`ebcd7f4`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/ebcd7f4) instead keeps the artwork at constant size and expands an invisible axis-aligned `<foreignObject>` using `rotatedBoundingBox`. Static receipt and dossier cards still shrink because their visible layout cannot grow. [ADR 0009](docs/adr/0009-rotated-relic-sizing.md) records both algorithms, the rejected result, and the rule added to [CLAUDE.md](CLAUDE.md), so a later agent cannot “simplify” the distinction away.

**Verification.** I swept the spoon, the most extreme aspect ratio, through 360° in the live placement preview and after placement. A script also checked all 16 presets every 15°. The replacement [passed CI](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/actions/runs/42499452026) with neither clipping nor visible size change.

## Intervention 4: correcting the test harness, not adding retries

Two CI runs failed because independently correct placement tests ran concurrently against one database and selected the same free surface. This was interference between test files, not evidence that production had lost its transaction checks. Both expected 201 and received 409 ([first failure](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/actions/runs/42208609821), [retry still failed](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/actions/runs/42209773623)). Retrying one assertion treated the symptom. I instead diagnosed the shared read-then-write race and changed the harness: [`5331034`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/commit/5331034) sets `fileParallelism: false` in [Vitest’s configuration](vitest.config.ts) and documents why. The next [clean CI run passed](https://github.com/comp4020-agentic-coding-studio/comp4020-final-pengyue-stella/actions/runs/42210212213). This made the suite slightly slower, but removed interference without hiding genuine placement conflicts. This is the workflow I kept: use the agent to generate and inspect quickly, but make each recurring failure improve the guide or sensor for every later session.

## Limits of the evidence

The [restart](spec/persistence-restart.test.ts) and [Séance](spec/seance.test.ts) checks establish persistence and delivery, not whether the museum sustains curiosity. Future work would run longer sessions with independent visitors, observe where they stop or become confused, and test whether competing accounts actually change their exploration and contributions. Green checks establish reliability, not the whole experience.
