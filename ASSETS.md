# Asset credits and provenance

This file describes the assets used by the current illustrated museum. Older
presentation experiments remain documented in the ADRs and Git history.

## Illustrated rooms

`public/assets/gallery-scenes/` contains **The Hall of the Fifth Door**, four
main gallery views, and earlier source/reference images. Dedicated close-up
reference files remain in the asset set for compatibility and provenance, but
no current object opens the four empty close-up scene records.
They are project-specific illustrated artwork rather than screenshots of a
live Three.js room. Main scenes use a wide 1672px footing so the same bounded
pan/zoom system can be applied consistently.

The decision to replace a technically functional but visually generic 3D room
with illustration is documented in `docs/adr/0004-illustrated-scenes.md`. The
later single high-resolution foyer replacement (collapsing four stitched
low-resolution facings into one `entrance-hall-v2.png`) is documented in
`docs/adr/0010-foyer-repair-and-archive.md`.

Most built-in object previews are not separate downloaded thumbnails: the
client crops the relevant traced object directly from its own scene image,
preserving the relationship between the dossier and the item the visitor
selected. A smaller set of distant or partially occluded objects instead uses
a purpose-made high-resolution reconstruction of the same painted object,
stored under `public/assets/builtin-details/` and wired through
`GENERATED_BUILTIN_DETAIL_IMAGES` in `server/src/world.js`; the client
(`renderBuiltinObjectVisual` in `public/app.js`) prefers this detail image
when one exists for an object and falls back to the ordinary scene-art crop
otherwise.

The catalog in `server/src/relic-presets.js` records each image's natural
dimensions, gallery category, subtype, compatible physical surfaces, anchor,
and default scale. A donor chooses one of these images; the server validates
the declared `visualId` instead of accepting arbitrary URLs or uploads. This
small vocabulary keeps visitor contributions visually coherent while still
allowing different titles, stories, positions, scales, accounts, and votes.

### Provenance — the 8 new relic presets (2026-11-04)

The original four presets' own provenance was never recorded; this section
only covers the eight added this session.

Generated by `tools/generate-relic-assets.py`, a dev-time-only script (never
imported by the server, never part of `pnpm check`/CI — the same status as
the historical `tools/build-scenes.py`). Each image is a single Pollinations
(`image.pollinations.ai`, free/keyless, "sana" model) generation at 900×900,
requested against a flat colour backdrop (green by default; magenta for
`clock-that-keeps-no-hour`, whose brass/glass rendered with a green patina
that collided with the default key colour), then background-removed by the
script's own hue-based chroma key (samples the backdrop's actual hue from the
image's own border ring, rather than assuming a fixed RGB, since the model
doesn't render a perfectly flat backdrop) and feathered to avoid JPEG-fringe
haloing. Raw generations and the manifest of prompts/timestamps are kept in
`tools/sources/relic-gen/` (gitignored staging, not shipped). Every output
was manually reviewed for subject correctness and cutout cleanliness before
being copied into `public/assets/donated-relics/`.

Known limitation: `locked-nursery-diary.png` has a faint dark shadow-halo
artifact at two corners, inherited from the source photo's own lighting
rather than a keying defect; judged an acceptable real-photo artifact.

### Provenance — Gothic refresh and four additional presets (2026-11-05)

`tarnished-silver-spoon.png` was replaced with an OpenAI ImageGen edit that
follows the project's own `design/references/04_spoon_reference.png`: the new
version restores the eye embedded in the spoon bowl and removes the failed
pink/green chroma-key fringe. The four additional presets listed above were
generated with OpenAI ImageGen as isolated transparent cutouts using the
museum's existing Victorian cabinet-of-curiosities direction: obsidian,
mahogany, tarnished brass, parchment, dried rose, warm amber museum light,
realistic aged materials, and no surrounding room or display surface.
Outputs were manually reviewed, resized to a 900px maximum dimension, and
their alpha channels retained before being added to the curated catalog.

- `dried-flower.png`
- `tiny-key.png`
- `dust-scratches.png`
- `tiny-lock.png` (retained as an extra and to keep existing saved sticker ids valid)

The previous programmatic SVGs remain only as unreferenced historical source
files. `server/src/relic-presets.js` now serves the PNG set; stable ids such
as `antique-label`, `glowing-rune`, and `eye-symbol` were deliberately kept
so donations already stored in SQLite continue to render after the artwork
replacement. Effects with fine alpha (cobweb, crack, glow, and dust) were
kept at up to 768px; the other stickers use the same maximum for consistent
customiser quality.

## Accessory overlays (superseded, unshipped)

`public/assets/accessories/` contains stackable overlay illustrations
explored as an alternative route to relic personalisation before the overlay
stickers above shipped. They are not referenced by any current server or
client code and a donor cannot currently add one to a relic — kept only as
provenance for the attempt and its one known failure mode:

- `glasses.png` — Spectacles
- `ring.png` — Signet Ring
- `hat.png` — Mourning Hat

Generated the same way and by the same script as the new relic presets above
(Pollinations + hue-based chroma key), staged and reviewed the same way.
`ring.png` required a `blue` backdrop override: its gold band collided with
the default green, and a magenta override (as used for the clock) in turn
collided with the ring's own red gemstone.

A fourth accessory, an eyepatch, was attempted and **not shipped**. Across 8
independent regenerations, every prompt wording that named "eye," "patch,"
"pirate," "costume," or "mask" — including ones with explicit anti-human
negatives ("no face, no person, no human") — returned a photo of a masked or
costumed person, or in one case an unrelated skull medallion, rather than a
standalone object. This looks like a strong, specific bias in the underlying
model's learned associations for this one object, not a bug in this script's
backdrop/keying logic (every other asset, including ones sharing individual
words like "leather" or "strap," generated correctly). Left as a known
follow-up: either a different image source/model, or manual illustration,
would be needed to fill this one slot.

## Visitor apparitions

`public/assets/ui/visitor-ghost-masculine.png`,
`visitor-ghost-feminine.png`, and `visitor-ghost-small.png` are transparent
project-specific apparition templates. A visitor chooses one at the entrance;
the selected id is shared with room-scoped presence so other visitors render
the same form. Colour and placement variation are applied by the interface,
not stored as separate image files.

## Interface and procedural assets

The Floor Plan, SVG object glows, placement-surface outlines, focus effects,
ornamental frames, and dust are generated from HTML/CSS/SVG or small browser
scripts. Object and surface geometry comes from hand-authored shapes in
`server/src/world.js`, not from an invisible rectangular image map.

## Background music

`public/assets/audio/museum-ambient-theme.m4a` is a licensed audio track
(not an original composition, and not synthesized in-browser — an earlier
version of `public/world/ambient.js` instead generated its own ambience
purely from Web Audio oscillators/noise; that approach was replaced with
this track at the project owner's direction):

- Title: 【童话氛围音乐】满月秋夜，南瓜灯照亮蜜溪谷小镇｜万圣节氛围音乐丨放松 · 休息 · 阅读
- Source: <https://www.bilibili.com/video/BV1KEJe6oEGr/>

It plays looped through `public/world/ambient.js`'s `#sound-toggle` control,
gated behind a real user gesture (never autoplayed on load), and defaults to
on for a visitor who has never explicitly chosen either way — an explicit
toggle choice is always remembered and respected on later visits.

Three.js r169 remains vendored at `public/vendor/three.module.min.js` under its
MIT licence. It is no longer part of the museum rooms or the normal donation
flow. `public/world/artifacts.js`, `furniture.js`, and `textures.js` survive as
a defensive still-preview fallback for an old database row that has no
curated `visualId`. New donations must choose a curated PNG and never enter
that fallback.

## Hotspot-tracing dev tool (not shipped to visitors)

`public/tools/vendor-sam/` vendors SlimSAM (a distilled Segment Anything
model) and its JS/wasm runtime (transformers.js, onnxruntime-web) for
`public/tools/hotspot-editor.html`, a dev-only page that traces each scene's
hand-editable SVG object shapes (see `docs/adr/0011-object-shaped-interaction.md`).
This is the one deliberate exception to `CLAUDE.md`'s zero-runtime-dependency
rule: never linked from museum navigation, never imported by any `server/` or
`public/` app code, and the museum's own shipped dependency graph is
unaffected by its presence. On disk it is roughly 62MB (models, runtime, and
one wasm backend).

## Retired assets

The crit-10 free-roam prototype used Kenney **Mini Characters** (v1.0, 2024,
CC0 1.0 Universal) as a rigged avatar base together with Three.js loader
addons. The switch away from embodied free-roam removed the model, loader
addons, `avatar.js`, and the live room renderer. This history is retained in
Git and `docs/adr/0003-scene-exploration.md`; those files are not shipped by
the current app.

The retired procedural room furniture remains described in earlier commits
and ADRs. Current room architecture and lighting are pixels in the illustrated
scene assets, while live DOM/SVG layers provide interaction, presence, and
visitor-placed relics.
